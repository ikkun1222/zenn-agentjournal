テキストと質問リストを渡すと0〜1のスコアを返す判定APIを、分類タスクでどう使うか。選択肢は2つあります。1行につき1つの問いを投げて閾値で切る「直接判定」と、1行につき12〜14の観点をスコアリングし、その生スコアを自分のラベルで学習した線形モデルに入れる「特徴量抽出」です。

この2つを3つの分類タスクで実測しました。入力トークンは3,410万、テスト行数は5,500行、APIの実費は1.43ドルです。

結論を先に書きます。分解が効くのは、1つの問いがすでに弱いタスクだけでした。それ以外の場所では、トークンを2倍払って誤りの性質を悪化させます。

論点は「判定APIを導入するかどうか」ではなく「どの粒度で聞くか」です。粒度を細かくすれば精度が上がるという期待は、今回の実測では3タスクのうち1タスクでしか成立しませんでした。粒度を上げたときに何が起きるかを、精度・誤検知・コストの3面から見ていきます。

## 何を比較したのか

### 直接判定と特徴量抽出

判定API（TypeSafe AIのJev）は、テキストと質問のリストを受け取り、質問ごとに0〜1の校正済みスコアを返します。使い方は2通りです。

1. **直接判定** — 1行につき1問（「これはプロンプトインジェクションか」）を投げ、スコアを閾値で切ります。
2. **特徴量抽出** — 1行につき12〜14問（「指示が本文の中に隠れているか」「難読化されているか」「ペルソナ変更か」）を投げ、生スコアを自分のラベルで学習したロジスティック回帰に投入します。

2つ目は役割の分離が利点です。抽出はネットワーク越しの高コストな工程なのでJSONLにキャッシュして再開可能にし、学習はローカルで何度でも無料で回せます。重みを変えても課金は発生しません。問題は、この分解が「よく練った1問」に勝つのかどうかです。

### 比較した3タスクと検証方法

| タスク | データ | 学習 / テスト |
|---|---|---|
| プロンプトインジェクション検出 | 難問ベナイン339件（手法に言及するだけの正常文）＋外部セット2,060行 | 4,391 / 942 |
| 日本語NLI（JNLI、JGLUE） | entailment / contradiction / neutral の one-vs-rest | 8,000 / 2,434 |
| 仕訳行 → 借方勘定科目 | 実データの会計エクスポート、上位12科目（全体の87%） | 4,907 / 2,101 |

ベースラインは無料かつローカルです。文字2/3-gram、単語bigramのNaive Bayes、多数クラスを用意しました。比較は同一行に対するMcNemar検定とペア付きブートストラップ区間で行っています。

## 実測結果

| タスク | 直接判定 | 12〜14次元＋重み | 最良のn-gram |
|---|---|---|---|
| インジェクション（テスト） | 0.837 | **0.952** | 0.954（単語bigram） |
| インジェクション（外部セット） | **0.956** | 0.840 | 0.381 |
| 難問ベナイン（全て正常） | **偽陽性率1.5%** | 偽陽性率37.2% | 偽陽性率14.2% |
| 日本語NLI | 0.837 | **0.908**（+7.0pt、p<1e-4） | 0.553 |
| 仕訳 → 科目 | 0.400 | 0.911 | **0.949** |

### 分解が効くのは、1つの問いが弱いときだけ

- 仕訳分類は、12択を1問で聞いた直接判定が0.400まで崩れたタスクです。分解はそこで+51pt伸びました。
- 日本語NLIは+7.0pt。インジェクションは分布内で+11.6ptでしたが、外部セットでは11.6pt失いました。直接判定がすでに0.956だった場所です。
- 「分解のほうが優れている」のではなく、「自分の1つの問いが失敗する場所でだけ優れている」という整理になります。

### 分解は表層マーカーを再発見する

学習された重みの最大の正係数は `obfuscated_encoding`（+1.80）と `hidden_in_content`（+1.62）でした。これはデータセットの表層分布であり、意図ではありません。単語bigramがインジェクションで12次元と並び、仕訳行では上回った理由もここにあります。

### 語彙的な近道がないタスクでは勝つ

日本語NLIでは、n-gramベースラインがすべて多数クラス（0.553）以下でしたが、次元モデルは0.908に達しました。内訳はcontradictionクラスが0.921対0.654です。誤りの出方も直交しており、仕訳行ではn-gramのみで解けた行が138、次元のみで解けた行が63ありました。そこでn-gramのクラス確率を追加入力として積むスタッキングを行うと0.970（+2.33pt、CI [+1.57, +3.14]）になりました。

### 偽陽性が運用を決める

手法に言及しているだけの正常テキストに対し、12次元モデルは37.2%を誤検知しました。直接判定は1.5%ですから26倍です。難問ベナイン170件を学習に足しても34.3%、表層的な次元を落とすと40.7%と悪化しました。閾値を偽陽性率5%程度まで締めると、攻撃検出が0.952から0.770へ18pt落ちます。直接判定の確率を13番目の特徴量として入れるのは勧めません。校正が壊れ（偽陽性率46.0%、外部セット0.956→0.788）、良い直接判定は独立した判定者として残すべきです。

## コストの内訳

入力単価は100万トークンあたり0.042ドルで、API自身の利用カウンタから読み取りました。

| 方式 | トークン / 行 | ドル / 1,000行 | ドル / 100万行 |
|---|---|---|---|
| n-gram / TF-IDF | 0 | 0 | 0 |
| 直接1問 | 444〜619 | 0.019〜0.026 | 19〜26 |
| 12次元 | 1,010〜1,036 | 0.042 | 42 |
| 14次元 | 1,136〜1,154 | 0.048 | 48 |
| スタッキング（次元＋n-gram確率） | +0 | +0 | +0 |

次元1つあたり40〜50トークンで、その大半は問い自体の文言です。差は2〜2.6倍にすぎず、得られる判断に比べれば小さい。請求額の側にお金はありません。月100万行・正常トラフィック20%という条件では、偽陽性率37%は約74,000行が人手レビューに回ることを意味します（1.5%なら約3,000行）。約590時間の作業に対し、トークン代は月27ドルです。請求額を最適化してレビュー負荷を3倍にするのは、桁を間違えた最適化です。抽出は一度きりで、学習用の4,391行は0.19ドル、以降の再学習や閾値変更はキャッシュを再利用します。設計を誤ったときの損失は、請求額ではなく人の時間として現れます。

## 現在の運用フロー

| 手順 | 確認すること | 打ち切り条件 |
|---|---|---|
| 0 | ラベル付き200行（可能なら実データ） | — |
| 1 | n-gram / TF-IDFのベースライン | 目標達成 → 判定APIは不要 |
| 2 | 1行1問の直接判定 | 精度0.95以上 → 分解は改悪 |
| 3 | 次元＋学習した重み | 語彙的な近道がないタスクに限る |
| 4 | 次元とn-gram確率のスタッキング | 誤りが直交するとき+2.3pt |
| 5 | 直接判定を主、次元をセカンドオピニオンに | 難問ベナインで必ず学習する |

ガードレール用途では、厳しめの閾値で直接判定を1回呼び、その判定が不確かな行だけ小さな次元モデルに相談します。分類はn-gramを先に置き、残差に次元を積む構成です。多クラスでは12択を1問で聞かないこと。今回の計測で最悪の結果でした。

## 限界と注意点

- 12〜14次元は自作なので、この数値は筆者の次元設計を説明するものです。「手法に言及している」と「手法を使っている」を分ける次元が、偽陽性の次の検証課題です。
- 日本語NLIのラベルにはノイズと55%のneutral偏りがあるため、0.908は上限ではありません。外部インジェクションセットには類似行に矛盾するラベルがあります。
- 仕訳タスクは上位12科目が対象で、入力に貸方側の科目も含みます。素の銀行明細ではなく「文脈付きで取り込む」ケースです。
- 結果は3タスクの計測であり、次元の設計や閾値の決め方を変えれば数値は動きます。
- 出力トークンは価格に含めていません。CLIは入力のみを報告するため、846,765トークンを別途計測しています。

## まとめ

まず最も安いベースラインを書いてください。n-gramが通れば判定APIは不要です。1つの問いが0.95に届くならそれを維持します。分解は2.5倍のコストで、正常入力を26倍誤検知します。次元スコアは1つの問いが本当に弱いタスクにだけ使い、置き換えるのではなく安いモデルと積んでください。

順序の意味は単純です。安い工程から試し、効果が確認できた段階でだけ次の工程を足します。判定APIは最初に置くものではなく、n-gramと1問の直接判定が失敗したときに初めて使う工程という位置づけになります。

ここまでで測った範囲では、単一の問いが弱くないのに分解が勝ったタスクはありませんでした。今回の計測は入力トークン3,410万・実費1.43ドルで、生データと再現手順は英語版の [agentjournal.dev](https://agentjournal.dev/blog/llm-judge-vs-feature-extraction/) にまとめています。心当たりのある方がいれば、次元は問いが知らない何を知っていたのか、教えていただけると助かります。あなたのタスクなら、最初の1問はどう書きますか？
